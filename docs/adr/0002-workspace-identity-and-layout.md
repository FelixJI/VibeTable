# ADR 0002：工作区以稳定 UUID 作为顶层隔离单元

- 状态：已接受
- 日期：2026-07-28
- 决策者：VibeTable 产品与工程

## 背景

现有产品把“工作区”同时用于表格集合、文档目录和一个全局数据根。名称、路径和运行时数据服务没有共同的稳定身份，无法安全切换、恢复或重新定位。

## 决策

- 每个工作区使用永久稳定的 UUID；名称和路径不是身份，允许重名。
- 设备级 `WorkspaceRegistry` 只保存投影和位置，不成为工作区内容权威。
- 直连布局使用 `<root>/files` 与 `<root>/.vibetable`；镜像布局另有本机 activity root。
- 一次最多发布一个活动 session。所有工作区请求和事件绑定 `workspaceId + sessionEpoch`。
- 无工作区、位置离线、manifest 损坏或密钥缺失时，Shell 仍可启动到 Workspace Center。
- 旧 `.backup` 工作区在开发期明确拒绝并要求重建，不做隐式迁移。

## 后果

路径变化只需 UUID 校验后重新关联；切换必须重绑所有 workspace-scoped 服务并使旧 epoch 失效。工作区创建与连接必须经过路径能力探测。

## 被否决的方案

- 以显示名称或绝对路径为身份：重命名、盘符变化和重名会破坏引用。
- 继续使用全局数据根并在 UI 模拟工作区：无法形成恢复与审计边界。
