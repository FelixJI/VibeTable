# ADR 0014：PDF 提取先验证成熟适配器，再决定替换有限扫描器

- 状态：提议；未采纳适配器，未授权产品依赖或运行时切换
- 日期：2026-09-06
- 代码基线：`main@770fb96e88a5b7e271ba791a13b7f00c5313f8fd`

## 背景

[A6](../plans/2026-08-29-vibetable-maturity-convergence-and-runtime-evolution.md#a6pdf-提取能力决策)
要求先完成支持范围、corpus、预算和维护成本决策，不能直接启动替换项目。
[支持资格](../plans/2026-09-05-pdf-support-qualification.md)保留原生文本 PDF 承诺。
现有扫描器无法按页树排除页面外文本，也没有实现一般字体映射；修补这些问题需要 xref、对象、字体和
filter 子系统，已超出局部字符串扫描修复。已知 MUST 差距满足进入替换 ADR 的条件，但不证明候选已合格。

## 提议

下一步优先资格验证固定版本 PdfPig 及严格解码边界，保留其他成熟 adapter 的比较结果；暂不扩建自研通用
PDF parser。PdfPig 默认设置本身不满足拒绝语义，不能直接接入生产。以下约束必须随候选一起验证：

1. 解析器确定的页面可达性和字体映射决定正文；不再从整个文件扫描文本运算符。
2. 解码流完整结束且符合输入、单流、累计和输出预算后才接纳结果。解析 warning 的保守拒绝方案仍需验证
   误拒范围；不得依赖异常消息文本分类，亦不能把已知缺字码映射当作无文本。
3. 库没有可靠硬取消契约时，使用每任务进程边界；进程终止必须结算任务且不接纳部分正文。原型的进程退出
   测量不等于产品 worker、grant、残留文件或 Job Object 已完成。
4. Go 保持搜索任务、派生 generation 和事务 owner。adapter 只提取文档，不能获得 PocketBase 写路径或
   成为另一业务 authority；单文档拒绝与 rebuild 级失败按现有契约分别处理。
5. 支持范围不缩窄为本项目生成的 PDF，不增加 OCR、密码交互或版面恢复承诺。

## 证据与代价

[候选发现记录](../research/2026-09-06-pdfpig-qualification-observations.md)记录正反证据，而非资格通过报告。
默认 PdfPig 能正确提取真实中文文档，但会吞掉部分 Flate 错误；严格探针必须同时处理压缩协议结束和 parser
交给 filter 的边界。固定 SharpZipLib 的严格 inflater 提供了一条可验证路径，也增加一个维护和许可对象。

当前原型未 fork parser；xref 的声明长度适配仍是上游行为耦合，升级时必须保留正负回归。字体 warning
拒绝也可能误拒合法文档。它们是采用前必须接受并验证的维护成本，不能因真实样本成功而省略。

普通 .NET 构建目录中的八个候选依赖 DLL 合计 5,979,648 字节；这是未压缩发现值，不是正式包体增量。
Apache-2.0、MIT 及 PdfPig 捆绑资源的完整 NOTICE、SPDX/SBOM、离线 Windows x64 发布包仍待验证。

## 接受条件与回退

本 ADR 只有在代表性 corpus、明确拒绝语义、完整资源/输出/取消边界、索引事务、许可和发布资格均有
可复验证据后，才可改为“已接受”并选择具体 adapter。届时单独实施 worker 生命周期和提取入口切换，保持
每个 PR 的完整意图和独立回滚；禁止双写、隐式 fallback 或用旧扫描器掩盖候选失败。

当前文档可独立回滚，不改变产品行为。若候选不能满足任一采用条件，保留负证据并回到方案比较，不能把
MUST 降成不支持、降低门禁或仅以生成样本通过结束 A6。
