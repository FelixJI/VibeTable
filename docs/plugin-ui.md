# 插件 UI 规范 v1

本规范统一 VibeTable 插件的主题、布局、表单与状态反馈。新建或修改的可见插件页面应遵循下列
要求；[简化 ERP](../examples/plugins/simple-erp/README.md)是本规范的参考实现。
现有其它示例尚未逐一按此规范迁移，不能据此宣称已全部符合。

这是**插件作者的实现约定**，不是新 Host 协议，也不是自动绘制 UI 的组件库。
宿主提供隔离页面、授权 API、展示上下文、原生确认和任务回执；插件负责 DOM、CSS、表单、
键盘操作和错误展示。可使用原生 HTML 或在包内构建前端框架，但不得访问父页 DOM 或依赖远程 CDN。
页面入口、隔离与打包的强制规则见[插件开发指南](plugin-development.md)，接口见 [API 参考](plugin-api.md)。

## 1. 主题与密度

### 数据来源

- 通过 `context.current()` 应用首次展示快照，通过 `context.onChanged()` 持续跟随；只注册监听
  不读取首次快照，会导致刚打开时主题错误。异步首次请求不能覆盖已经收到的更新。
- `mode` 控制 `color-scheme` 和亮/暗回退色；`density` 控制紧凑/舒适间距。切换不得重新查询、
  重建表单或丢失输入。`locale` 表示用户偏好，不意味着 SDK 自动翻译插件。
- 关闭页面时取消监听并 `dispose()`。展示偏好不是身份或权限，不参与数据授权。

### 宿主 token

| CSS 变量 | 用途 |
| --- | --- |
| `--vt-plugin-bg` | 页面和输入控件背景 |
| `--vt-plugin-surface` | 表头、表单与提示面板背景 |
| `--vt-plugin-text` | 正文 |
| `--vt-plugin-text-muted` | 辅助说明，不用于替代关键错误文字 |
| `--vt-plugin-border` | 分隔线与控件边框 |
| `--vt-plugin-primary` | 当前导航、主动作强调、键盘焦点 |
| `--vt-plugin-danger` | 错误边框、未知结果警示 |
| `--vt-plugin-radius` | 控件与面板圆角 |
| `--vt-plugin-space-unit` | 基础间距，缺省 4px |

这些名字来自宿主 `pluginTheme.ts`。插件应消费宿主值并提供亮/暗回退；每次替换快照时删除不再
存在的旧 inline token，让 CSS 回退生效。插件自己的布局变量使用独立前缀，例如 `--erp-*`，
不要冒充新的 `--vt-plugin-*` 宿主合同。宿主尚未提供成功/警告/on-primary token，不可假定它们存在。

不能假设所有主题的主色都适合叠加白字。ERP 使用主色边框、字重和中性背景强调主动作。
警告、错误、成功必须同时有文字；高对比模式保留系统颜色，不关闭 `forced-color-adjust`。

### 尺寸基线

| 项目 | 约定 |
| --- | --- |
| 正文 / 辅助文字 | 14px / 不小于 12px；密度不缩小正文字号 |
| 页面标题 / 区块标题 | 24px / 18px，保持 h1 → h2 层级 |
| 基础间距 | 按 4px 单位组织，常用 8、12、16、24px |
| 舒适 / 紧凑控件最小高度 | 36px / 32px |
| 表格单元格垂直留白 | 舒适 12px，紧凑 8px |
| 宽屏页面 | 居中，参考最大宽度 1440px、内边距 24px |
| 窄屏页面 | 700px 以下内边距 16px；工具栏换行，表单按可用宽度收为一列 |

这些是本仓页面的默认设计值，不是 Host 的像素强制校验。确有业务差异可以调整布局，但不得
隐藏关键操作、压缩文字至不可读或移除焦点标识。

## 2. 页面结构与导航

使用“标题与返回入口 → 业务导航 → 状态反馈 → 工具栏 → 数据区 → 编辑区 → 任务明细”的顺序。
反馈区域放在 `aria-busy` 数据区之外，避免等待状态阻止辅助技术播报错误。

- 搜索有可见 label，不能只依靠 placeholder。新建、刷新、导出使用明确动词；说明导出是否受
  当前筛选影响。ERP 搜索仅影响当前列表，导出为整表原值。
- 导航按钮用 `aria-pressed` 表示当前页；链接导航用 `aria-current`。不要声明 `role=tab`
  却不实现对应键盘行为。原生 button 支持 Tab、Enter、Space，不用可点击 div 替代。
- 表格使用 caption、thead 和 `th scope=col`；行操作提供包含记录名称或订单号的可访问名称。
  只让表格容器横向滚动，容器可键盘聚焦且有名称；页面、工具栏、表单不能依赖横向滚动操作。
- 目标在 320 CSS px 宽度及浏览器放大到 200% 时仍能读取说明和操作表单。表单列最小宽度
  不得超过当前容器；长消息换行。不要使用固定屏幕高度裁掉页脚或保存按钮。
- 普通页面切换不制造新窗口。application 内使用同文档导航；返回平台走 `ui.navigation.back()`。
  业务文字用 `textContent` 等安全文本渲染，不拼接到 HTML。

## 3. 表单和草稿

1. 每个输入有可见名称、稳定 id 和必填说明，`label` 与输入关联；单位在标签或帮助文字中明确。
   金额区分“元输入”和“分存储”，不能把显示文本直接写回原值字段。
2. 根据数据选择控件：邮箱用 email，整数数量用 number/min/step，金额用 decimal 输入提示
   并显式检查精度。浏览器和插件校验不能替代权威数据层校验。
3. 提交前检查必填、格式与业务范围。错误写在字段附近，用 `aria-invalid=true` 和
   `aria-describedby` 关联错误；给出简短总提示并聚焦第一个错误。错误时不生成写入预览。
4. 修改字段时清除该字段的旧错误标记；重新提交时重验。服务端冲突等跨字段错误在反馈区说明
   原因和下一步，不随意归因到某个输入。
5. 提交前捕获输入快照，再禁用表单和重复提交入口；否则 `FormData` 会漏掉已禁用字段。
   等待宿主确认时说明“等待确认”，不能提前提示成功。拒绝和失败保留输入。
6. 本页切换、刷新、关闭编辑区、返回平台可能丢弃草稿时先提示。默认聚焦“保留表单”，Escape
   与保留等价，并恢复先前焦点。提示未解决时阻止冲突操作，不能继续执行原动作。
   关闭编辑区后焦点不能留在隐藏内容中。

ERP 的离开提示是**非模态的页内确认区**，不声明 dialog，也不模拟原生数据批准窗口。真正的
模态对话框必须使用可访问的对话框机制并管理焦点与返回。插件不能阻止宿主强制退役/工作区关闭；
未持久保存的草稿在这些情况下会丢失，必须在使用说明中如实说明。

## 4. 状态反馈

反馈至少说明“发生了什么、输入/数据是否保留、下一步怎么做”，不能只用颜色、转圈或通用“失败”。
普通进度用稳定的 `role=status` 区域；需要立即注意的错误用 `role=alert`。不要让两处 live region
重复播报同一条错误。加载区设置 `aria-busy`，交互能力按真实状态控制。

| 状态 | 展示和行为 |
| --- | --- |
| 加载 | 明确正在读取；没有数据时显示加载占位，禁止依赖数据的操作 |
| 未加载 / 加载失败 | 明确未获得数据和恢复入口，不呈现为“0 条” |
| 空表 / 无搜索结果 | 区分“暂无记录，可新增”和“没有匹配记录” |
| 校验失败 | 保留输入、标明字段、聚焦首错，不向 Host 提交 |
| 等待确认 | 禁止重复提交，说明需在宿主确认；不伪造批准按钮 |
| 成功 | 只基于权威回执；保存成功但刷新失败须明确区分，不能引导重复新增 |
| 拒绝 / 取消 | 分别说明未批准或已取消；取消请求受理不等于写入已回滚 |
| 冲突 / 数据失效 | 保留输入，停止使用旧 guard 保存，提示刷新核对；不自动覆盖 |
| 结果未知 | 独立、持续警示并锁住写入口；刷新/导出/主题变化不能清除，不自动重试 |

未知结果的恢复需要核对权威数据和宿主任务。ERP 保守地要求核对后重新打开应用，不把普通刷新
当作确认未写入。任务明细显示宿主状态，不能由插件自报进度或用某个任务成功覆盖另一个未知结果。
临时通知仅作补充，不能承载唯一的校验错误、数据丢失警告或提交终态。

## 5. ERP 实现与验证入口

| 约定 | 实现 |
| --- | --- |
| 首次主题、更新、移除旧 token、密度 | `src/app.ts` 的 `applyTheme` 与初始化；`ui/style.css` |
| 流式布局、表格局部滚动、焦点和高对比 | `ui/index.html`、`ui/style.css` |
| 字段标签、校验、首错定位、拒绝保留 | `field`、`validateForm`、提交处理 |
| 草稿离开、Escape、恢复焦点 | `leave`、`cancelLeave`、`closeEditor` |
| 状态区、持续未知警示、重复提交保护 | `status`、`availability`、`run` |

示例路径为 [`examples/plugins/simple-erp`](../examples/plugins/simple-erp/README.md)。
修改这些行为时运行：

```powershell
Push-Location examples/plugins/simple-erp
npm run typecheck
npm test
npm run build
Pop-Location
Push-Location desktop/web-grid
npm run typecheck
npm test -- src/components/plugins/simpleErpSurface.test.ts
Pop-Location
```

DOM 回归应验证首次主题及切换不丢草稿、字段错误不发请求、离开取消恢复焦点、重复提交受阻、
未知警示不被刷新覆盖。DOM 测试不能证明真实渲染、字体、缩放、高对比或读屏效果；这些需真实
浏览器/WebView2 验证。是否截图服从当前任务要求，截图不是行为测试的替代品。
