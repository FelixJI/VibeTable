# 自我更新能力评估

评估日期：2026-08-01

## 结论

VibeTable 当前没有可供终端用户使用的自我更新功能。

仓库已经具备可靠的发布物生产链路：GitHub Actions 构建并验证自包含的
Windows x64 便携包，随后向 GitHub Release 上传版本化 ZIP 和 SHA-256 文件。
这些能力保证“发布物可生成、可校验”，但不会让正在运行的桌面应用发现、下载
或安装新版本。

## 已有能力

- `.github/workflows/release.yml` 构建并上传
  `VibeTable-v<version>-win-x64.zip` 与对应 SHA-256。
- `scripts/build_next.py` 生成自包含桌面宿主、Python BFF、PocketBase sidecar、
  Web UI 和发布清单，并在构建目录中原子交换候选产物。
- `desktop/publish-layout.json` 固定包内组件版本和启动路径。

## 关键缺口

- 客户端没有更新渠道、版本查询或机器可读 feed。
- 没有下载器、包签名/发布者校验、断点与失败恢复策略。
- 没有进程外引导程序来停止组件、替换正在使用的文件并重启应用。
- 没有安装事务、回滚、跨版本兼容检查或更新失败遥测。
- 当前分发物是便携 ZIP，没有安装器负责升级和卸载生命周期。

`scripts/build_next.py` 的原子交换只发生在构建机的 `dist/` 目录，不能替换用户
机器上正在运行的程序，因此不构成运行时自我更新。

## 后续建议

如果要实现自我更新，应单独立项选择 Windows 安装/更新框架，并至少覆盖：
发布签名与信任根、稳定/预览渠道、进程外更新器、原子安装与回滚、数据格式
兼容、代理/离线环境、杀软误报证据以及从真实旧版本升级的端到端测试。
