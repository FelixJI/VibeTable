# VibeTable 数据表历史查询与安全恢复设计

日期：2026-07-22
状态：已由用户确认

## 目标

为本地 Directus 业务表提供可用的整表审计历史、单行/单元格历史和安全恢复能力，并通过与现有 VibeTable 风格一致的 Web UI 暴露。

## 范围

### 历史范围

- 整表：查看当前表全部修订，支持统一搜索、时间范围、操作者、操作类型、字段和记录筛选。
- 单行：查看一条记录全部可读字段的历史。
- 单元格：自动限定一条记录的一个字段。
- 只支持单行或单单元格恢复；不支持多选批量恢复。
- 整表历史是审计和检索入口，不支持整表恢复到某个时间点。

### 展示与搜索

- 默认时间倒序，每页 50 条，支持加载更多和刷新。
- 同一服务端 Activity/请求产生的多记录修订聚合为一个变更组，展开查看逐行、逐字段差异。
- 历史条目显示相邻版本的 `before → after`；恢复预览显示 `current → target`。
- 统一搜索匹配当前有权读取的记录主键/显示名、字段名、历史前后值文本、操作者名和修订 ID。
- 搜索在后端执行；不可读历史值不得通过内容或结果数量侧漏。

### 恢复

- 单元格恢复只写目标字段；整行恢复写目标版本中明确存在的所有可恢复字段。
- 目标版本不存在的新字段保留当前值；明确历史 `null` 才写回空值。
- 所有恢复均经过预览和二次确认；短时令牌绑定范围、当前状态、目标修订和 schema revision。
- 整行预览后任一可恢复字段变化则冲突；单元格只校验目标字段；归档记录校验归档状态和版本。
- 恢复成功必须生成新修订，刷新当前行、表格和时间线；不进入本地 Ctrl+Z/Ctrl+Shift+Z 栈。

### 不可写回字段

- 主键。
- Directus `meta.readonly=true` 字段。
- 数据库 `schema.is_generated=true` 计算/生成字段。
- 自动维护的创建/更新用户和时间等系统字段。
- 当前用户无更新权限或不在有效更新能力中的字段。
- 当前 schema 已删除、不可读或目标值与当前类型不兼容的字段。
- 这些字段可在有读取权限时展示，但预览必须标注跳过原因；没有任何可恢复字段时禁用确认。

### 关系字段

- 多对一和文件引用在目标存在且权限允许时可恢复，并显示安全的可读名称。
- 一对多、多对多等复合关系只有在后端可验证完整恢复时开放；否则展示变化并明确跳过，禁止部分写入。
- 目标不可见或不存在时不得泄露内容。

### 已删除记录

- 数据行删除坚持软归档，不提供物理删除入口。
- 工具栏历史菜单提供“已删除记录”，跨应用重启列出当前表的归档记录。
- 默认选中删除前最后版本，也允许用户选择更早版本；一次只恢复一条记录。
- 没有归档能力的表禁用删除/恢复并解释原因。

### 能力与数据源

- 当前产品只提供本地表入口，不新增外部数据源 UI。
- VibeTable 新建和接管的业务表默认开启历史查询与安全恢复能力。
- 仍需在运行时检查 Directus 修订能力、字段元数据和当前用户权限；能力不足时保留入口并展示原因。

## UI

- 工具栏提供历史入口：无选择时打开整表历史；单行/单元格选择时进入对应范围；菜单包含已删除记录。
- 普通单元格右键同时提供“查看此字段历史”和“查看此行历史”。
- 表格左侧增加窄行号栏，点击行号明确选择整行。
- 使用右侧历史抽屉承载搜索筛选、时间线、变更详情、恢复预览和确认。
- 延用现有 `--vt-*` design tokens、明暗主题、紧凑密度、Naive UI 和 Lucide 图标；视觉方向为克制、高密度、审计工具式。

## 验收

- Python 合同、服务和 RPC 测试覆盖查询范围、搜索权限、相邻差异、分组、字段分类、令牌、冲突、归档恢复和新修订。
- C# 合同、gateway、dispatcher 和 WebView 消息路由测试覆盖三段式流程。
- Vue store/service/component/Workspace 集成测试覆盖入口、范围、筛选、加载、预览、冲突、成功刷新、空态和错误态。
- 定向测试、lint/typecheck、相关 .NET 测试通过；实现后执行 Standards/Spec 双轴独立审查。
