# 插件逻辑模型 v1

模型声明位于原生 API 3.x manifest 的 `permissions.model`，合同为 `vibetable.plugin-model.v1`。声明包含稳定 `modelId`、递增整数 `version` 和最多 16 个实体；每个实体最多 64 个字段。实体与字段使用稳定逻辑 `key`、用户可读 `label`。同一模型版本不能改变定义。

支持 `text`、`number`、`bool`、`date`、`dateTime`、`email`、`url`、`relation`。数字显式选择 `integer` 或 `float64`，沿用原生数字存储语义，不承诺任意精度整数或精确十进制。关系两端均须声明目标 `entity`、反向 `field` 与自身 `cardinality`；创建时使用原生双向关系、`restrict` 删除策略。每个实体须有至少一个标量字段，优先使用首个文本字段作为关系显示字段，否则使用首个标量字段。未知合同、物理字段、SQL 和脚本声明被拒绝。

`client.model.configure({mode:"create"})` 请求原生精确预览；`mode:"map"` 先由原生窗口选择现有表与字段。插件不能获取未授权工作区目录，也不能提交映射或批准参数。预览显示具体表、字段、操作、数字精度和关系。名称冲突、类型、精度损失或关系不兼容以字段路径诊断，拒绝写入；映射不会转换原值。

确认后复用统一 schema domain：创建表、添加字段、创建原生关系。每步业务事务同时写入不可变的插件审计进度，复用现有写协调器 receipt。没有全局回滚承诺；`completed/total` 表示已提交步骤数，反向关系的一次事务算一步。`model.read()` 和 `model.status({requestId})` 从工作区持久状态读回 `pending`、`partial`、`failed` 或 `completed`，未创建的计划表不出现在公开进度绑定中。失败不自动重放，重新配置未失效计划会复用原计划身份与已完成范围。

只有当前启用安装、当前安装 revision、完整完成且与当前声明一致的绑定能派生数据权限。字段逐个列举并包含 `id`；用户扩展字段和升级新增字段不会自动授权。安装、模型或工作区变化使旧预览失效；升级后必须再次原生确认。已确认计划遇到外部 schema 更改会阻断，并保留准确已完成范围。

部分初始化后禁用再启用，新的确认计划只继承已提交表与字段的 canonical ID；尚未创建的表重新进入精确计划，确认之前不会补建。已提交对象丢失会报缺失诊断，不能用空表替代。并发请求的失败状态在写事务内读取最新进度，不能覆盖另一个请求已完成的结果。映射接受与完成均检查原生字段迁移写锁；迁移切换权威字段时也重新检查模型核心保护。

绑定使用 canonical table/field ID；用户修改显示名称不会失联。绑定核心表、字段的删除、退役、转换及不兼容定义修改在原生 schema authority 拒绝，用户扩展字段仍可正常编辑。禁用、卸载与清理插件私有存储不会移除已建立绑定或核心保护。业务余额、跨表事务及服务端业务规则不属于本模型合同。

`examples/plugins/model-conformance` 使用真实生产 SDK；离线测试宿主明确返回 `plugin_api_unsupported`。真实 WPF/WebView2 场景 `54-plugin-models` 通过正常打包、安装、原生 SendInput 确认覆盖空工作区取消后重新初始化、三表创建、异名手动映射、原生重命名与合成用户字段值保留、版本升级。随后正常退出首个 Host，以第二个真实进程打开同一 workspace，核对新 session epoch、持久绑定与原值。逐步提交中断、安装 revision 变化和并发恢复另有真实 PocketBase 回归。原生输入仅允许受控 GitHub CI 的当前 Job-owned Host，执行前再次核对身份与前景窗口。
